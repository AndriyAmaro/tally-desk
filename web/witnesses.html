Witnesses: clocks nobody here controls

A hash chain proves a record was not edited after it was written, but whoever runs it could rewrite the whole chain, or cut the end off. What stops that is a copy of the head held somewhere the operator cannot reach. Every hour the head is stamped in Bitcoin and signed, with no key of ours, in the public Sigstore transparency log; it is also written to Ethereum Sepolia and sits in git history. This page re-checks each of those in your browser: it reads the proof, asks two independent block explorers, the transparency log and a public Ethereum node, and compares what they say with the ledger it just downloaded. Nothing below is a number we typed.

1. Does the ledger still agree with every head that was stamped?

checking…

Each hour the head (sequence number and hash) is saved as ledger/timestamps/<seq>.json and stamped. If someone cut the end off the ledger, or rewrote its history and re-hashed it so the chain still verifies, the ledger would disagree with a head that was already stamped. This is the check that catches both.

2. Bitcoin, through OpenTimestamps

The proof says: this digest, put through these hash steps, becomes this value, which is written in the header of Bitcoin block N. Your browser reads the proof (ots.js), recomputes the digest of the saved head, replays the steps, and asks two public explorers for that block's merkle root. A green line means the head existed, byte for byte, no later than that block was mined, and neither explorer nor we can change that.

The newest proofs are pending for a few hours: the calendars have promised to include the head, and the Bitcoin block comes later. That is normal, and the table says so instead of showing a green line it has not earned.

3. Ethereum Sepolia, through the Chainlink CRE workflow

asking a public Sepolia node…

The contract only accepts strictly increasing sequence numbers, so an anchored head can never be overwritten. This is a testnet. Two routes write here, and each transaction says which: the CRE workflow run with cre workflow simulate --broadcast from the operator's machine, and, after each new head is published, from GitHub's runners, cre/anchor/direct.ts, which is not the CRE runtime (this account cannot create the CRE API key CI would need) but runs the same checks with the same code: two publications agree on the head, its dossier re-derives its own verdict, the Data Feed agrees on Sepolia and mainnet; then it hands the same report to the same forwarder, with the workflow name gh-actions in the report header. The history above, read from the contract's own events and each transaction's input, shows the real cadence, every gap and the route of every anchor.

4. Sigstore transparency log, signed by the GitHub workflow

asking the public log…

Every hour a workflow (.github/workflows/rekor.yml) signs the saved head with no key and no secret: GitHub tells Sigstore which repository and which workflow is running, Sigstore issues a certificate that lasts minutes and names that identity, and the signature goes into Rekor, a public log that records its own time. Your browser asks Rekor for each entry, checks that the digest the log holds is the sha256 of the head it just downloaded, and reads the certificate to see who signed. It does not check the certificate chain or the log's inclusion proof: for that, run cosign verify-blob --bundle ledger/rekor/<seq>.bundle.json --certificate-identity-regexp '^https://github.com/AndriyAmaro/verdict-desk/.github/workflows/rekor.yml@refs/' --certificate-oidc-issuer https://token.actions.githubusercontent.com ledger/timestamps/<seq>.json. The log's clock and the signer's identity are the point: neither belongs to the person who runs the ledger.

5. Git history

asking GitHub…

The weakest witness: the commit times belong to the operator's own account. Its value is that every clone made earlier still holds the old history, so a rewrite would show.

6. We attacked our own verifier

loading…

Reproduce it: python3 -m verdict_desk battery (the seed is the head hash, so you get the same attacks). The two attacks the hash chain cannot see alone are listed on purpose: cutting the end off, and rewriting history and re-hashing every later record. They pass verify by design and are caught only by the stamped heads in section 1.

What none of this proves

  • That a decision was right, or that a source said something true. A timestamp proves the bytes existed by a time, not that they are correct.
  • Who wrote the record. Integrity after recording is the claim, not authorship at collection time.
  • That the Sepolia anchor is current: it is a testnet and its cadence is shown above.
  • That nobody could attack the way we did not think of. The battery counts the attacks we tried, no more.
